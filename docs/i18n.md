# Internationalization Guide

Edgefolio uses app-owned translations, not browser auto-translation. Each supported language has a locale URL such as `/en`, `/ko`, or `/es/dashboard`.

## Current Supported Languages

The supported language list is managed in one place:

- `lib/i18n-config.ts`

Current locales:

| Locale | Display name | Intl locale | Default currency |
| --- | --- | --- | --- |
| `en` | English | `en-US` | `USD` |
| `ko` | 한국어 | `ko-KR` | `USD` |
| `ja` | 日本語 | `ja-JP` | `USD` |
| `zh-CN` | 简体中文 | `zh-CN` | `USD` |
| `es` | Español | `es-ES` | `USD` |

`USD` is used as the default display currency because demo trading data is USD-based. The locale still controls number, date, percent, and currency formatting style.

## Translation File Location

Translation files live in:

- `messages/en.json`
- `messages/ko.json`
- `messages/ja.json`
- `messages/zh-CN.json`
- `messages/es.json`

Every file must have the same key structure as `messages/en.json`.

## Add A New Language

For a translator or non-developer:

1. Copy `messages/en.json`.
2. Rename the copy to the new locale code, for example `messages/fr.json`.
3. Translate the values only. Do not rename keys such as `dashboard.kpis.netPnl`.
4. Keep placeholders exactly the same, for example `{count}`, `{symbol}`, `{date}`, `{plan}`.
5. Do not translate user data examples such as tickers, strategy names, broker names, tags, or trade notes unless they are UI copy.

For the developer connecting the new language:

1. Add one entry to `localeConfig` in `lib/i18n-config.ts`.
2. Add the JSON import and dictionary entry in `lib/i18n.ts`.
3. Run:

```bash
npm run i18n:check
npm run i18n:scan
npm run typecheck
npm run lint
```

The language selector reads from `localeConfig`, so the new language appears in the dropdown once the locale is configured.

## Translation Key Rules

- Keep keys stable. Code references keys like `trades.addTrade`.
- Translate values, not keys.
- Keep placeholders unchanged and in the same spelling.
- Keep button labels short and action-oriented.
- Keep KPI labels compact so cards and table headers stay readable.
- Use `TRANSLATION_GLOSSARY.md` for trading terminology.
- Do not translate user-entered content: trade notes, tags, strategy names, broker names, exchanges, or ticker symbols.

Good:

```json
"deleteConfirm": "Delete the {symbol} trade from {date}?"
```

Bad:

```json
"deleteConfirm": "Delete the {ticker} trade from {day}?"
```

The second example breaks the app because the placeholder names changed.

## Date, Currency, Number, And Percent Formatting

Locale formatting is managed in:

- `lib/i18n-config.ts`
- `lib/utils.ts`
- `components/i18n-provider.tsx`

Each locale has:

- `label`: shown in the language dropdown
- `intlLocale`: passed to `Intl.DateTimeFormat` and `Intl.NumberFormat`
- `currency`: default currency for formatted money values

Components should use `useI18n()`:

```tsx
const { formatCurrency, formatDate, formatNumber, formatPercent } = useI18n();
```

Do not call `toLocaleString()` directly in new UI code. Use the formatter helpers so each language is consistent.

## Validation Script

Run:

```bash
npm run i18n:check
npm run i18n:scan
```

The script checks:

- configured locales in `lib/i18n-config.ts`
- matching `messages/{locale}.json` files
- invalid language codes
- missing translation keys
- extra translation keys
- placeholder mismatches such as `{count}` vs `{total}`
- source code references to missing translation keys
- possibly unused translation keys

To fail on possibly unused keys as well:

```bash
npm run i18n:check -- --strict-unused
```

Unused-key detection is conservative. Some keys are used dynamically, so review warnings before deleting translations.

## Translation QA Checklist

For each supported language, open:

- `/{locale}`
- `/{locale}/pricing`
- `/{locale}/login`
- `/{locale}/signup`
- `/{locale}/dashboard`
- `/{locale}/trades`
- `/{locale}/analytics`
- `/{locale}/calendar`
- `/{locale}/insights`
- `/{locale}/settings`

Check:

- Buttons do not wrap awkwardly.
- Cards remain balanced.
- Table headers are readable.
- Chart labels do not overlap.
- Mobile width has no horizontal scroll.
- Language switching stays on the same page.
- Dates, numbers, currency, and percentages look natural.
- No raw keys such as `trades.addTrade` appear on screen.
- Dark mode and light mode both remain readable.

## Human Review Needed

Some copy should still be reviewed by a fluent human before production:

- legal or risk disclaimers
- pricing and plan language
- AI insight answer text generated from rule-based analytics
- broker/import terminology that may vary by market
- trading terms where a community prefers English over translation
